# 机汇 OpportunityManage · 用户手册(User Manual)

> 适用版本:v0.5 · 本手册分三部分:**部署指南(以 BytePlus 云为例)**、**功能使用手册**、**FAQ 与故障排查**。

---

# 第一部分 · 部署指南(BytePlus 云)

## 0. 先了解部署形态

机汇当前是**纯静态单页应用(SPA)**:构建产物是一个 `dist/` 目录(1 个 HTML + 2 个 JS + 1 个 CSS),**没有后端、没有数据库**,用户数据保存在访问者自己浏览器的 IndexedDB 里。因此:

- 部署 = 把 `dist/` 托管到任何能提供 HTTPS 的静态站点服务上;
- **必须启用 HTTPS**:浏览器的到期通知等能力只在安全上下文(https:// 或 localhost)下可用;
- 服务器资源占用几乎为零,不需要为它购买高配置。

BytePlus 上有三种可行方式,推荐顺序:**方式 A(TOS 静态托管 + CDN)> 方式 C(容器)> 方式 B(ECS + Nginx)**。

## 1. 构建产物(三种方式通用的第一步)

环境要求:Node.js ≥ 18(建议 20)。在仓库根目录执行:

```bash
npm ci          # 按 lock 文件安装依赖
npm run build   # 类型检查 + 生产构建,输出到 dist/
```

构建成功的标志:`dist/` 下有 `index.html` 与 `assets/` 目录。项目已配置相对路径(`base: './'`),放在域名根目录或任意子路径下都能正常运行。

## 2. 方式 A(推荐):TOS 对象存储静态托管 + CDN

BytePlus 的对象存储叫 **TOS(Torch Object Storage)**,原生支持静态网站托管;配合 **BytePlus CDN** 获得全球加速与 HTTPS。

**步骤:**

1. **创建 Bucket**:BytePlus 控制台 → TOS → Create Bucket。地域选离用户最近的;访问权限设为公共读(Public Read),或保持私有并完全通过 CDN 回源访问;
2. **开启静态网站托管**:进入 Bucket → 静态网站(Static Website)设置 → Index Document 填 `index.html`;Error Document 也填 `index.html`(防止手输错误路径出现裸 404);
3. **上传 `dist/` 内容**:把 `dist/` 目录**里面的全部文件**(不是 dist 文件夹本身)上传到 Bucket 根目录,保持 `assets/` 子目录结构。可用控制台上传,或用 TOS 的命令行工具/S3 兼容工具做脚本化上传;
4. **绑定 CDN**:BytePlus CDN → 添加加速域名(你的域名,如 `crm.example.com`)→ 源站类型选对象存储/该 Bucket 的静态网站 Endpoint → 上传/申请 HTTPS 证书并开启强制 HTTPS;
5. **配置缓存策略(重要)**:
   | 路径 | 缓存时长 | 原因 |
   | --- | --- | --- |
   | `/assets/*` | 1 年 | 文件名带内容哈希,内容变了名字就变 |
   | `/index.html`(及 `/`) | 不缓存或 ≤60 秒 | 发版后用户立即拿到新入口 |
6. **DNS**:在你的域名服务商处把域名 CNAME 到 CDN 提供的接入地址;
7. **验证**:浏览器访问 `https://你的域名/`,应看到工作台与演示数据。

**日常发版流程**:`npm run build` → 覆盖上传 `dist/` 内容 → 在 CDN 控制台刷新(Purge)`/index.html` 与 `/` → 完成。

## 3. 方式 B:ECS 云服务器 + Nginx

适合你已有一台 BytePlus ECS 的情况。最低配置即可(1 核 1G 足够)。

```bash
# 1. 服务器上安装 Nginx(以常见发行版为例)
sudo apt install nginx        # Debian/Ubuntu
# 或 sudo yum install nginx   # CentOS 系

# 2. 把本地构建好的 dist/ 上传到服务器
scp -r dist/* user@服务器IP:/usr/share/nginx/html/

# 3. 使用仓库内置的配置(含 gzip、长缓存、入口不缓存)
#    参考 deploy/nginx.conf,放到 /etc/nginx/conf.d/default.conf
sudo nginx -t && sudo systemctl reload nginx
```

之后:在 ECS 安全组放行 80/443 端口;用 certbot 或 BytePlus 证书服务配置 HTTPS;域名 A 记录指向 ECS 公网 IP。

## 4. 方式 C:容器部署

仓库内置 `deploy/Dockerfile`(多阶段构建:Node 构建 → Nginx 托管),适用于 BytePlus 容器服务(VKE)或任何 Docker 主机:

```bash
docker build -f deploy/Dockerfile -t jihui-opportunity-manage .
docker run -d -p 80:80 --restart=always jihui-opportunity-manage
```

推到 BytePlus 的镜像仓库后,即可在其容器服务中以该镜像创建工作负载,暴露 80 端口并在入口层(负载均衡/网关)终止 HTTPS。

## 5. 上线核对清单

- [ ] `https://` 打开正常,地址栏无"不安全"提示
- [ ] 硬刷新(Ctrl+F5)后页面正常(验证缓存策略)
- [ ] 新建一条商机 → 刷新页面仍在(IndexedDB 持久化正常)
- [ ] 顶栏铃铛可开启通知(浏览器弹出权限询问即为正常)
- [ ] 设置 → 导出 JSON 备份能下载文件
- [ ] 手机浏览器打开布局正常

**重要提醒**:数据按"浏览器 + 域名"隔离。正式域名上线后,之前在测试入口(单文件版/Pages/预览链接)录入的数据不会自动出现——用旧入口"设置 → 导出 JSON 备份",在新域名"导入数据"即可整体迁移。

## 6. 各访问入口对照

| 入口 | 适用场景 | HTTPS | 数据位置 |
| --- | --- | --- | --- |
| BytePlus 正式部署 | 团队日常使用 | ✅ | 各自浏览器 |
| GitHub Pages | 免费公开演示 | ✅ | 各自浏览器 |
| 单文件版 single.html | 离线试用、发给他人 | file:// | 本机浏览器 |
| Claude 私有预览 | 快速内部评审 | ✅ | 本机浏览器(.xlsx 导出受限) |

# 第二部分 · 功能使用手册

## 1. 五分钟上手

首次打开自带一套**演示数据**(8 个商机、9 位联系人、9 条跟进、5 条想法),先随意点点找感觉;正式使用前到 **设置 → 重置为演示数据** 旁边确认后清空,或直接删改演示数据。

三个核心理念,决定了所有功能的用法:

1. **商机为中心**:联系人、跟进、想法都挂在商机上,打开商机详情就是全貌;
2. **永远有下一步**:每个进行中的商机任何时刻都应有一条待办跟进——完成一条时系统会默认引导你建下一条;
3. **优先级贯穿全局**:P0 紧急(红)/ P1 重要(橙)/ P2 普通(蓝)/ P3 观察(灰),四类对象通用。

## 2. 工作台

打开产品的第一屏,回答三个问题:

- **今天该做什么** → 「今日跟进」面板:逾期的置顶标红,勾选即完成;
- **哪些商机最要紧** → 「高优先级商机」:P0/P1 商机及其下一步;若出现橙色"无下一步跟进"警示,点「立即补建」;
- **最近发生了什么** → 「最近动态」时间线。

顶部四张卡:进行中商机数、在途总金额(含按赢率加权值)、本周待跟进(含逾期数)、本季赢单率。

## 3. 商机

- **新建**:右上角「+ 快速新建 → 商机」。只有名称和客户公司必填;填了"主要联系人"姓名会自动创建/复用联系人;
- **看板视图**:按阶段六列(线索→初步接触→需求确认→方案报价→谈判→赢单),**直接拖拽卡片到目标列即变更阶段**——赢率自动更新为该阶段默认值,时间线自动记录;拖入"赢单"列会先确认;
- **列表视图**:右上角切换;支持按阶段、优先级、**标签**筛选(两个视图共用筛选);
- **详情页**:点击卡片/行进入。顶部**阶段步进条可直接点击推进**;「新建跟进」会自动关联本商机与主要联系人;「标记输单」必须填写原因(会写入时间线,是最有价值的复盘数据);「编辑」可改金额、赢率、优先级、标签等;删除商机会连带删除其跟进与时间线(想法只解除关联,不删)。

## 4. 跟进项

- **完成跟进(核心闭环)**:点击条目前的方框 → 弹出完成弹窗 → 填写跟进结果(选填,写入商机时间线)→ 默认勾选"完成后立即创建下一次跟进",点「完成,去建下一次」一气呵成。误勾可在"今日已完成"分组里点方框撤销;
- **列表视图**:按 已逾期 / 今天 / 本周 / 以后 分组,组内按优先级排序;悬停条目出现铅笔图标可编辑;
- **日历视图**:右上角切换。按截止日铺在月历上,颜色=优先级,左侧红条=已逾期,划线灰色=已完成;点条目编辑;鼠标悬停日期格出现「+」,点击即建当天的跟进;
- **到期通知**:点顶栏**铃铛**开启(首次会请求浏览器权限)。跟进截止前 15 分钟或已逾期时弹桌面通知,每条只提醒一次,点通知直接回到跟进页。

## 5. 联系人

记录姓名、公司、职位、**角色**(决策者/影响者/使用者/把关者)、电话、微信。"最近联系时间"由完成跟进自动刷新;超过 14 天没联系且有进行中商机的人会红字提醒天数。行尾「编辑」可修改或删除(删除会自动从商机与跟进中解绑,主要联系人自动顺延)。

## 6. 想法

销售灵感的"先记下来再说"入口:顶部输入框**回车即存**(默认进入"待评估")。每周回顾一次待评估的想法:有价值的点「**转为跟进项**」(自动带出关联商机,3 天后截止)或「**升级为商机**」(带出标题与内容的预填表单);暂时没用的「搁置」,以后可「重新激活」。已采纳的想法保留原文并链接到转化结果。

## 7. 全局搜索与快捷键

| 操作 | 快捷键 |
| --- | --- |
| 全局搜索(跨商机/联系人/跟进/想法) | `⌘K` / `Ctrl+K`,回车打开第一条结果 |
| 关闭弹窗/搜索 | `Esc` |
| 想法速记保存 | 输入框内 `Enter` |

## 8. 统计

右上角切换统计周期(本月/本季/今年/全部):

- **六项指标**:新增商机、赢单(数量+金额)、输单、赢单率、平均成交周期、平均客单价(数据不足显示"—");
- **月度赢单趋势**(近 6 个月)、**在途阶段快照**(含按赢率加权的金额——这是更真实的业绩预测)、**输单原因分布**(输单时填的原因在这里变成复盘资产)、**来源分析**(哪个获客渠道赢单率高)、**跟进活跃度**(近 6 周完成跟进数)。

## 9. 设置与数据管理(侧栏「设置」)

- **导出 Excel**:商机/联系人/跟进项/想法四张表,中文表头,可发给他人查看,也可以修改后**再导入**(有 ID 的行更新、无 ID 的行新增,导入后会汇报数量);
- **导出 JSON 备份**:含时间线的完整备份,**换电脑/换浏览器/换域名迁移数据就用它**;导入 JSON 会整体覆盖当前数据(有确认提示);
- **重置为演示数据**:清空当前数据恢复出厂演示(需确认)。

# 第三部分 · FAQ 与故障排查

**Q:数据存在哪里?会不会丢?**
存在你当前浏览器的 IndexedDB 里(旧版本的 localStorage 数据会在首次打开时自动迁移),不经过任何服务器。清除浏览器"站点数据"会清掉它,所以重要数据请定期「导出 JSON 备份」。

**Q:换了电脑/浏览器/域名,数据没了?**
数据按"浏览器 + 域名"隔离,不会自动同步。在旧环境导出 JSON 备份 → 新环境导入即可。多设备实时同步需要等多用户后端版本。

**Q:多人能一起用吗?**
当前是单机版:每个人打开看到的是自己浏览器里的数据。团队协作(账号、共享、分配商机)在 Backlog 中,见 requirements.md。

**Q:到期通知不弹?依次检查:**
① 站点是否为 HTTPS(http 下浏览器禁用通知);② 顶栏铃铛是否为绿色开启态;③ 浏览器地址栏站点设置里通知权限是否为"允许";④ 操作系统是否开了勿扰/专注模式;⑤ 通知每条只提醒一次,已提醒过的不会重复。

**Q:导入 Excel 提示"导入失败"?**
最常见原因:文件不是由机汇导出的模板(缺少"商机/联系人/跟进项/想法"工作表)、或文件损坏。请先「导出 Excel」拿到标准模板,在其上修改后再导入;单元格里的未知阶段/优先级会自动回退为默认值,不会导致失败。

**Q:同时开了两个标签页,数据会乱吗?**
两个标签页各自在内存中工作,后保存的会覆盖先保存的("最后写入者胜")。建议同一浏览器只开一个标签页使用;跨标签页实时同步在 Backlog 中。

**Q:能存多少数据?**
IndexedDB 容量通常为数百 MB 起,文字型 CRM 记录几万条无压力。

**Q:忘了部署后怎么更新版本?**
见第一部分各方式末尾的发版流程;核心永远是三步:`npm run build` → 上传新 `dist/` → 刷新 CDN 的 `index.html`(或重启容器)。
