# 需求汇总(截至 V0.5)

> 本文档是产品需求的唯一权威清单:每条需求标注**状态、落地版本、验证方式**。设计依据见 [design.md](design.md),流转规则见 [workflows.md](workflows.md),UI 规范见 [ui-design.md](ui-design.md),测试用例见 [test-plan.md](test-plan.md)。

## 1. 产品定位(原始需求)

商机管理的 Web 软件:**商机、联系人、跟进项、想法**四类信息有序管理,支持**优先级**。演进过程中确认的核心原则:商机为中心、永远有下一步(跟进闭环)、优先级贯穿全局、录入零阻力。

## 3. 非功能需求

| 维度 | 要求 | 现状 |
| --- | --- | --- |
| 存储 | 本地持久、容量≥数万条记录、换环境可迁移 | IndexedDB + JSON 备份迁移 ✅ |
| 性能 | 首屏包精简;重依赖按需加载 | 主包 ~74KB gzip,xlsx 独立异步 chunk ✅ |
| 健壮性 | store 层边界防御(空必填/幽灵 ID/重复操作/脏数据钳制) | ✅ V0.4,单测锁定 |
| 质量门槛 | 每次迭代:tsc + build + 单测 + E2E 全绿方可提交 | 当前 86 单测 + 43 E2E ✅ |
| 可访问性 | 焦点可见、语义控件、reduced-motion、色彩非唯一信息载体 | ✅ |

## 4. 规划中(Backlog,建议优先级)

| 优先级 | 需求 | 说明 |
| --- | --- | --- |
| P1 | 多用户后端 | Node + Fastify + Prisma + SQLite→PostgreSQL:账号登录、多设备同步、商机分配/转移;现有 JSON 备份可直接灌入 |
| P1 | 自定义阶段与标签管理 | 设置中增删改阶段(含默认赢率)与标签字典 |
| P2 | 跨标签页同步 | BroadcastChannel,消除"最后写入者胜" |
| P2 | 搜索增强 | 结果键盘上下选择;搜索历史 |
| P2 | 回款/合同备忘 | 赢单后的交付与回款跟踪(design.md V2) |
| P3 | URL 路由 | 页面/商机可直链分享 |
| P3 | 大数据量优化 | 列表虚拟滚动(>5k 条场景) |
| P3 | 提醒升级 | 服务端推送/邮件提醒(依赖后端) |
